# 逐拍歌词工作台（Beat Lyrics Studio）

一个本地运行的 Web 应用，用来制作 **逐拍歌词**（每个发音的时间点）与 **逐行歌词**（原文 / 翻译 / 注音），
在画布上实时预览成片效果，并用**离线逐帧渲染 + 硬件编码**导出视频。

> 界面语言为简体中文。推荐使用 **Chrome / Edge 114+**（视频导出依赖 WebCodecs，项目目录读写依赖 File System Access API）。

## 2. 项目文件格式

项目是**一个目录**（约定扩展名 `.blsp`），用「打开项目」选择或新建目录后，所有改动会**自动保存**：

```
我的项目.blsp/
├── project.json          # 项目数据（JSON，UTF-8）
├── assets/               # 导入的图片 / 音频 / 视频（保持原始文件名）
│   ├── song.mp3
│   └── cover.png
└── cache/
    └── peaks-4096.json   # 波形峰值缓存（可安全删除，会自动重建）
```

导入素材时的规则：

- 素材被**复制**到 `assets/`。
- 若同名文件已存在**且内容不同**，会询问：**覆盖 / 保留现有 / 取消**。
- 若同名且内容相同（按 SHA-256 比对），静默复用，不打扰。
- 同一内容重复导入只占一份（按内容哈希去重）。

不支持 File System Access API 的浏览器会自动退化为「内存项目」，此时可用顶部的 **导出 ZIP** 保存整个项目。

## 3. 两个页面

### 3.1 歌词编辑页

左栏是**逐拍歌词**，右栏是**逐行歌词**；两者完全独立，没有任何自动填充关系。

#### 逐拍歌词

- 每一小节是一行时间轴：一条横向**主轴**，上面在每个**拍位置**画一个细高的竖直**刻度**；
  节拍序号画在刻度正下方，歌词字文本也挂在刻度位置的正下方。
  同一小节内所有刻度间距相等（除非设置了该小节的时间轴变换）。
- 默认整行铺满；**小节时间轴变换**（宽度缩放 + 横向位置）用于在小节拍数变化后重新对齐。
  例：原本每小节 8 拍，本小节改为 4 拍后刻度间距变成 2 倍；设置缩放 50% + 位置 25%，
  即可让时间轴居中且刻度间距与其它小节一致。**任何设置都会被夹取在行内，不会超出横向范围。**
  面板里还有「自动对齐 + 居中」一键完成这个计算。
- **插入事件**：先在工具栏选好「插入工具」，然后在轨道上**双击**。默认吸附 1/2 拍，
  可切换 1/1、1/2、1/3、1/4、1/6、1/8，或选 **1/N 自定义**输入任意分母。
  小节内拍数范围是 `[1, 拍数+1)`（第 0 秒 = 第 1 拍开始）。
- **选中**：点小节背景选中小节，点事件图标选中事件；两套选中状态**互相独立**，
  属性面板只显示当前选中对象能编辑的属性。
- **多选**：`Ctrl+点击` 加入/移出多选，`Ctrl+A` 选中当前小节全部事件。
- **重叠事件**：同一位置反复左键点击会在重叠的事件之间循环（每次把当前最上层那个压到最下层并选中下一个）。
  重叠判定看的是**指针处实际有几个图标**，而不是拍号是否相同。
- **移动**：拖动事件图标（跨小节也可以）。**删除**：选中后按 `Delete`，或**按住右键在轨道内滑动**
  批量标记、松开右键统一删除（可撤销）。
- **复制粘贴**：`Ctrl+C` 复制选中事件，`Ctrl+V` 粘贴到当前选中的小节。
- 事件方块已放大到易点击的尺寸，并有白色描边，保证图标在任何颜色下都能辨识。

八种事件：

| 事件 | 形态 | 含义 |
| --- | --- | --- |
| 歌词字 | 略高于主轴的圆角矩形，宽度可调 | 一个发音单元；文本显示在**图标正下方居中** |
| 设置 BPM | 音符 | 从此处起播放头改用新 BPM，上方显示 `bpm=…` |
| 暂停 | 暂停符号 | 播放头原地停留若干毫秒，上方显示 `…ms` |
| 强制行进 | 圆角矩形内含重复的 `>`，并铺一条覆盖带 | 覆盖一段时间轴（不能跨小节），播放头按指定毫秒匀速走完；带内左上方显示 `…ms` |
| 逐行歌词上一句 | 向上箭头 | 主歌词回退若干块，上方显示 `LRC→N` |
| 逐行歌词下一句 | 向下箭头 | 主歌词前进若干块，上方显示 `LRC→N` |
| 逐行歌词临时行开始 | `》` | 把某块加入临时行列表，上方显示 `LRC+N` |
| 逐行歌词临时行结束 | `《` | 把某块移出临时行列表，上方显示 `LRC-N` |

歌词字支持：**多个文本行**（例如上行假名、下行罗马音），每行内再用**分段**设置样式。
例如可以做出「粗体、上黄下绿的 `ノー` 换行 `noo`」。

强制行进区间内不允许存在其它事件，冲突的事件会被标红提示。

#### 逐行歌词

- 这里的一「行」准确说是「**块**」，一个块内可包含多个**子行**。
- 支持新增 / 删除 / 复制 / 上下移动块。
- **没有「整体文本」输入框**：要表达一整段文本时，只用一个分段即可。
  这样「整体」与「分段」不再有两套来源，编辑结果始终可预期。
- **样式全部挂在分段上**（不再有「整体样式」）：
  - **颜色用颜色栈**：只有一种颜色就是纯色，有多个颜色就是**由上至下的渐变**，
    用「＋色 / −」添加删除颜色，也可以选渐变预设。
  - 粗体、斜体、字号（占基准字号的百分比）、**ruby 注音**（样式跟随该段）。
- **输入框禁止换行**：一个分段就是一行文本；按回车会在该段之后再新建一个分段。
- 每个子行顶部都有**行内实时预览**，使用与播放画面完全相同的绘制代码，所见即所得。
- **主歌词**只有一块：决定播放时的竖直中心位置与突出显示。
- **临时行**由逐拍歌词的事件驱动：进入时该块移到主歌词下方，与主歌词一起突出显示并**挤占**其它行的空间；
  退出时回到原本位置。播放页可调上下展示行数与各自的透明度。

#### 预览

顶栏的播放按钮可在编辑页直接预览。播放头在时间轴上向右移动，一小节结束立刻跳到下一小节；
逐行歌词同步高亮主行与临时行。可勾选「跟随播放头滚动」。

### 3.2 播放编辑页

左栏八组设置，中间是实时舞台，右栏是状态面板。

| 分组 | 内容 |
| --- | --- |
| 画布 | 尺寸预设（1080p / 720p / 4K / 竖屏 / 方形 / 宽银幕）、自定义宽高、背景纯色或渐变 |
| 专辑图 | 是否显示、选择图片、位置（点击或拖动设置中心点）、大小、圆角、阴影；黑胶光碟样式、底色、播放时旋转与转速 |
| 逐拍歌词 | 位置、**横向缩放 X 与纵向缩放 Y（分开设置）**、展示小节数（≥1）、当前/后续小节透明度、主轴与刻度样式、节拍序号、歌词字文本样式、扫过动画、**逐事件类型的图标与文本开关** |
| 逐行歌词 | 位置、字号、行距、对齐、上下展示行数、主行/临时行/普通行透明度、主行放大与颜色、注音样式 |
| 视频背景 | 选择视频、时间偏移、填充方式、缩放、透明度；**只播画面不播声音** |
| 特效 | 屏幕抖动、整拍脉冲、整小节脉冲、歌词字跳动、火星飘落、闪光；可设触发源、强度、时长、频率、颜色、粒子数 |
| 频谱 | 开关、形状（柱状 / 对称 / 波形 / 点阵）、方向、列数、位置、大小、颜色与渐变、增益、频率范围 |
| 导出 | 见下 |

所有位置与尺寸都用**归一化坐标**（相对画布），改变画布尺寸后布局自动等比缩放，无需重新摆放。

三个面板之间的**分隔条都可以拖动**来调整宽度，舞台下方的状态区也可以拖动调整高度；双击分隔条复位。

播放时：扫描线扫过的事件会**放大渐隐**；强制行进这类持续事件在**整段经过之后**才放大渐隐。

#### 音乐（音频）

编辑页顶部有一条**始终可见的音乐区**：

- 没有音乐时显示一个明显的「导入音乐文件…」入口，也支持把音频文件**直接拖进来**。
- 导入后显示文件名、大小、时长和**波形条**：波形位置直观反映当前的**音频偏移**
  （蓝色区域 = 音乐，黄色区域 = 歌词时间轴）。
- 点击波形条可以定位播放头；旁边有三个一键对齐按钮：
  「对齐开头」「音乐开场对准播放头」「音乐收尾对准时间轴」。
- 偏移很大时**不会出现谁卡住不动**的情况：播放头照常前进，
  音频起点在播放头之前（负偏移）就直接从音频内部开始播；音频起点在播放头之后（正偏移）
  则先进入「无声等待」，等播放头追上音频起点时音源立刻开始出声。
  反过来，如果歌词时间轴比音乐短，音乐会先结束、歌词继续走完；如果音乐比时间轴长，则音乐播完为止。

## 4. 导出视频

导出**不是**实时录制。它是剪辑软件式的两段式流程：

1. **离线逐帧渲染**：按 `i / fps` 逐帧调用与实时预览完全相同的渲染函数，
   逐行歌词状态按时间重放、频谱由离线 STFT 求值、视频背景逐帧 seek 取帧。
2. **硬件编码 + 封装**：通过 WebCodecs 的 `VideoEncoder` / `AudioEncoder` 编码，
   再用 [mediabunny](https://mediabunny.dev/) 封装为 MP4 或 WebM。

因此：

- 画质由**码率与分辨率**决定，不受设备实时性能影响（不会掉帧、不会因卡顿而音画不同步）。
- 导出耗时与视频时长**不成正比**，长视频也能导出。
- 音频按项目时间轴的偏移对齐后一次性编码。

可用容器与编码：MP4 = H.264 / HEVC / AV1 + AAC；WebM = VP9 / AV1 + Opus。
启动时会用 `isConfigSupported` 探测实际可用的编码，不支持时自动回退并在完成后提示
（例如 AAC 不可用时整体回退到 WebM + Opus）。若浏览器完全没有 WebCodecs，会给出明确的中文提示。

### 三个关键设计

**1. 拍 ↔ 秒的分段线性映射（`core/timeline.ts`）**

事件位置永远用「拍」表示；音频、播放头、导出用「秒」表示。两者之间不是简单比例，而是分段线性：

- 普通段：1 拍 = `60/bpm` 秒，`bpm` 由「设置 BPM」事件改变；
- 强制行进段：一段被压缩/拉伸的拍区间，用指定毫秒匀速走完；
- 暂停点：拍轴上宽度为 0，但在秒轴上占 `ms` 毫秒 —— 播放头原地不动。

因此「暂停」和「强制行进」自然成为时间映射的一部分：**播放头、编辑器预览、逐行歌词、导出渲染
全都共用同一套映射**，天然一致，不需要在每个消费方各写一遍逻辑。

内部拍号是 0 基的（第 1 小节第 1 拍 = 绝对拍 0），界面上显示为 1 基。这样「第 0 秒是第一拍开始」
和「`beat × 60/bpm` 就是时间」两个约束同时成立。

**2. 渲染是纯时间函数（`render/frameRenderer.ts`）**

`renderFrame(ctx, project, timeline, time, resources, opts)` 只依赖 `time`，不依赖上一帧、不依赖墙钟。
逐行歌词状态由 `LrcCursor.seek(time)` 确定性重放事件得到，特效粒子用固定种子的伪随机数定位。
这条不变量是「预览与导出完全一致」和「离线逐帧导出」的前提。

**3. 素材在项目目录内（`core/storage.ts`）**

用 File System Access API 直接读写真实目录，加载时保持可读性（保留原始文件名），
用内容哈希做去重与「同名同内容静默复用」的判断。

## 7. 已知取舍

- 导出的 MP4 使用 WebCodecs 的硬件 H.264/HEVC/AV1。**Firefox 目前不支持 `VideoEncoder`**，
  在 Firefox 上导出面板会给出提示；编辑与预览功能不受影响。
- 视频背景在导出时是逐帧 seek，速度取决于磁盘与解码器；素材很短时可以考虑先转码成帧内编码（如 ProRes / all-intra）来提速。
- 频谱背景不显示波形缩略图叠加层，波形仅用于素材条缩略图。
- 「火星飘落」的粒子从画布中上部整体飘落，没有定位到触发它的那个歌词字身上。
